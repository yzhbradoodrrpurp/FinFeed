# FinFeed 本机自选股平台

按需求实现 8 组指标、20 个数值列，加上 Ticker、Name 和交易日期。本机入口仅监听 `127.0.0.1`；云端入口通过 Passkey 验证私人账户，使用 PostgreSQL 持久保存自选股和持仓。无付费平台权限绕过，备用数据源密钥仅保存在私有配置中。

云端部署和迁移见 [DEPLOY.md](DEPLOY.md)；仓库根目录提供 Render 免费方案 Blueprint `render.yaml`。

## 使用

双击 `start.command`，或在仓库根目录运行：

```sh
./dashboard/start.command
```

启动后在默认浏览器打开 <http://127.0.0.1:8765>。关闭服务终端或按 Control-C 停止。已有 FinFeed 服务运行时，启动脚本直接打开页面，不重复启动。

首次运行需要 Python 3.11+ 和联网安装依赖。依赖固定为 yfinance 1.7.0；环境保存在被 Git 忽略的 `.venv/`。默认提供 AAPL、NVDA、MU、AMD、VRT、LRCX、VOO、QQQM，可添加 / 移除股票并按指标排序。Ticker 可以逗号或空格分隔，最多 40 个。

自选股、排序和持仓保存在 `dashboard/.local/state.json`；行情缓存保存在 `.cache/`，两者均不提交 Git。页面打开期间，每 60 秒自动刷新一次；手动刷新同样可用。行情普通读取缓存为 60 秒，自动 / 手动刷新会更新行情，5 秒内的重复请求合并，最多同时请求 2 个标的。上一轮仍在运行时跳过该次定时触发，避免请求堆积；网络失败保留已有快照并标记旧数据。关闭页面后停止刷新，浏览器后台节流或电脑休眠可能延迟定时器。刷新频率不改变 Yahoo 行情本身的延迟。

## 刷新频率

- 行情每 60 秒请求一次：价格、市值、52 周高低点、成交量及量比。
- 季度财务、增长率、实际 EPS 与 trailing EPS、Yahoo 盈利预测每天一次，以北京时间 00:00 切换更新日；页面打开后的下一轮行情请求触发，关闭页面期间不主动请求。
- P/E 使用最近已披露季度实际 EPS，Forward P/E 使用紧接着的下一财季预测 EPS；两列都按 `价格 /（单季 EPS × 4）` 简单年化，每分钟重新计算。单季乘以 4 不代表全年盈利预测，也不等于 LTM / NTM。缺少下一财季、EPS 非正或币种不同均明确留空。Forward EPS 与 Forward P/E 使用同一预测期，优先 Yahoo（通过 yfinance），缺失或财季不匹配时使用 Alpha Vantage。
- Alpha Vantage Key 放在被 Git 忽略的 `dashboard/.local/alphavantage.json`，格式为 `{"api_key":"你的 Key"}`，权限 600。预测响应每日缓存到 `.cache/alpha/`，本机按 UTC 日设置 25 次请求上限；实际供应商额度/权限限制也会明确处理。密钥不会传入浏览器、来源链接或异常信息。
- Alpha Vantage 失败时保留上一份预测并标记旧数据，当天不每分钟重试。财务更新失败时保留旧财务，详情分别显示行情、财务和预测检索时间。
- 2026-10-04 实测 Alpha Vantage AAPL 响应不足以计算未来四季 NTM；后续按用户要求改为最近实际季度 / 紧接下一预测季度的简单年化估值。

## 数据来源与限制（核验于 2026-10-04，Asia/Shanghai）

- 行情、财务和分析师预期：Yahoo Finance，经 [yfinance](https://ranaroussi.github.io/yfinance/) 读取。该项目并非 Yahoo 官方 SDK，适用于个人研究，数据的使用范围仍受供应商条款约束；不承诺实时、持续可用或覆盖所有市场。
- 原始来源入口：[SEC EDGAR](https://www.sec.gov/edgar/search/)、[SEC API 文档](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)。当前网络对 SEC Company Facts 的实际测试返回 HTTP 403，所以第一版使用 C 级 Yahoo 聚合财务值，不把它们标为直接提取的 SEC 数据。
- 每个标的提供北京时间检索时间、报价原始 UTC 时间、交易所时区、财季结束日期和逐字段来源。申报日期未从免费源可靠获得，因此明确缺失并提供 SEC 核对入口；数据期末不是公告日期。
- ETF 的公司 EPS、公司债务、营收和 FCF 不适用；ETF 的 P/E 也未用持仓加权或基金商估值替代。`BTC` 是 Grayscale Bitcoin Mini Trust 的 ETF 代码；BTC 现货应使用 `BTC-USD`，两者不能混用。
- 海外上市证券需输入 Yahoo 的完整代码，例如 `000660.KS`。报价币种和财务币种分别显示，金额不自动换成美元。不得把不同股票类别 / ADR / 本地上市证券静默合并。

## 持仓视图

切换到“Portfolio · 持仓”，点击“添加持仓”，每个 Ticker 填写总数量、每单位平均成本和成本币种。支持小数数量、编辑和删除记录；同一个 Ticker 只保存一条汇总持仓，已有记录通过“编辑”更新。持仓与 Watchlist 独立，移除自选股不会删除持仓，也不会停止该持仓行情更新。两者合计最多 40 个不同标的，每分钟共用同一次行情刷新。

计算口径：成本总额 = 数量 × 平均成本；市值 = 数量 × 最近常规时段价格；未实现盈亏 = 市值 − 成本总额；收益率 = 未实现盈亏 / 成本总额。零成本持仓的金额盈亏仍可计算，收益率不适用。不同币种分别汇总，不自动换汇。报价币种不符或报价缺失时，盈亏留空；汇总明确标出已估值项数，收益率仅使用已估值持仓的成本，仓位占比仅在同币种已估值持仓内计算。行情刷新失败时标出旧报价。

Watchlist（含手动排序）和持仓保存在本机 `dashboard/.local/state.json`，通过同源本地 `/api/state` 接口读取和保存，不提交 Git、不上传外部服务。保存采用临时文件原子替换，文件权限为 600；内容修改前自动备份到 `dashboard/.local/backups/`。首次打开且文件尚不存在时，会迁移当前浏览器的旧 localStorage 记录；文件存在后以文件为准；若旧版本误创建了默认列表，而当前浏览器有尚未迁移的自定义记录，会自动恢复一次。每次文件保存成功后也更新浏览器副本，并保留首次迁移前的 `finfeed.legacy-backup.v1`。清除浏览器网站存储不会删除文件记录；同一台机器不同浏览器可读取相同记录，多个窗口同时操作时同一列表以最后保存为准。请备份此文件；它不是可随意清理的行情缓存。平均成本请按券商口径填写（可以包含费用）；买卖、拆股后需更新数量和成本。本版不记录交易流水，不计算已实现盈亏、股息、现金余额或汇率收益。页面初始没有预填持仓。

持仓计算边界可运行 `node dashboard/test_positions.cjs` 验证。

## 手动排列 Ticker

点击“手动排序”，拖动列表中的标的，或使用“上移 / 下移”。调整立即保存到本机文件，页面重开和每分钟数据刷新都会保留顺序。点击列名仍可临时按指标排序；再点击“手动排序”恢复自定义顺序。新增标的追加到末尾。

## 指标口径

| 指标 | 数据或计算方式 |
| --- | --- |
| Ticker / Name / Market Cap | Yahoo 证券信息和公司市值；ETF 不用 AUM 替代市值 |
| Last Price / 52W High / Low | 常规交易时段最近成交价和供应商 52 周高低点，不混入盘后价 |
| Diluted EPS Q0 / Q−1 | 最新已披露财季与紧接的上一财季利润表 `DilutedEPS`；通常为 GAAP，实际取供应商口径 |
| Forward EPS Q0 | Yahoo `earningsTrend` 当前预测财季 `0q` 的分析师平均值；与已披露 Q0 可能不是同一季度，也可能是调整后 EPS；提供财季结束日期和分析师数量 |
| P/E · 已披露季度年化 | Last Price /（最近已披露单季 diluted EPS × 4）；EPS≤0 或币种不同时不适用 |
| Forward P/E · 下一季度年化 | Last Price /（紧接下一财季分析师平均 EPS × 4）；预测可能采用调整后盈利，不保证与实际 GAAP 口径相同 |
| Avg Volume 10 | 比较日以前 10 个完整交易日成交股数均值，排除比较日本身 |
| Volume vs. 10 | 比较日完整日成交股数 / 此前 10 日均量；盘中待收盘，非交易日明确显示最近交易日期 |
| Revenue Q0 | 最新披露单季 TotalRevenue |
| Debt Q0 | 最新披露财季末 TotalDebt；取供应商分类，租赁负债等口径跨公司可能不同 |
| FCF Q0 | 单季 OperatingCashFlow − 单季资本支出（支出取正数）；计算的非 GAAP 指标 |
| 各项 Growth Q0 / Q−1 | 全部为季度环比（QoQ）：Q0 / Q−1 − 1，以及 Q−1 / Q−2 − 1；营收和 FCF 比较单季金额，债务比较财季末存量；上一财季≤0或缺失时不计算 |

Yahoo 日线请求 `auto_adjust=False`，不做股息总回报调整，拆股处理遵循供应商。Q0 和 Q−1 的季度环比只需最近三个连续财季。财季间隔要求为 65–120 天，缺少上一财季时不跨季替代；绝不将缺失值设为零，也不混用不同财务口径。缓存 schema 已升级，旧版同比快照会失效并重新读取。

表格点击行可查看计算输入、日期、币种、来源和缺失原因。网页里的“本季度”统一解释为最近已披露财季，并不假设当前日历季度已经发布。

## 验证与结构

```sh
cd dashboard
.venv/bin/python -m unittest test_metrics.py
node --check public/app.js
```

- `server.py`：本机 HTTP 服务和输入限制。
- `data.py`：数据源适配、日期与币种、逐项来源、缓存和失败恢复。
- `metrics.py`：季度环比、上一财季匹配、P/E 和完整日量比。
- `public/`：原生网页，不依赖前端构建。

后续可接 SEC 财务解析或有授权的四季预测 API。公开部署之前需要重新核对数据许可、服务器访问控制和缓存范围；当前版本的个人研究数据不作为公共网站数据接口。

2026-10-03 本地验证：8 个默认标的全部取得真实行情；另外检查了 ASML 的币种差异和 MSFT 的添加 / 移除 / 持久化。5 项财务边界测试通过；浏览器完成了桌面 / 390px 小屏检查、添加格式校验、行详情、视图切换和排序验证，未发现控制台错误。页面内表格可横向滚动，小屏正文没有横向溢出。可选 WebMCP 功能仅在浏览器支持时注册；本次验证浏览器没有可用的 WebMCP 上下文，该项未验证。
